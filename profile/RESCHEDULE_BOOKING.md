# Перенос брони: инструкция для фронтенда

Пользователь может перенести бронь на другую дату и/или время. Переносить можно **любые слоты брони по отдельности**: если бронь на 2 часа, можно перенести один час, а второй оставить на месте, либо перенести оба.

> **Всё время (даты и слоты) — по Ташкенту** (`Asia/Tashkent`, UTC+5). Ничего конвертировать не нужно: что пользователь видит и выбирает, то и отправляем. Время сервера (Германия) клиента не касается.

## 1. Общая схема

```
GET  /profile/{telegram_id}         → список будущих броней (+ booking_id)
POST /free-slots                    → какие слоты свободны на выбранную дату
POST /profile/reschedule_booking    → сам перенос
```

Базовый адрес: `https://<host>{ROOT_PATH}` (если на сервере задан `ROOT_PATH`, он добавляется перед путём).
Все запросы — `Content-Type: application/json`. Эти три эндпоинта не требуют авторизации.

## 2. Шаг 1. Получить брони пользователя

`GET /profile/{telegram_id}`

```bash
curl "https://<host>/profile/123456789"
```

**Ответ 200:**

```json
{
  "name": "Иван",
  "phone": "+998901234567",
  "bookings": [
    {
      "date": "2026-11-12",
      "location": "A",
      "telegram_id": 123456789,
      "time_slot": "12:00-13:00",
      "booking_id": "a1b2c3d4"
    },
    {
      "date": "2026-11-12",
      "location": "A",
      "telegram_id": 123456789,
      "time_slot": "13:00-14:00",
      "booking_id": "a1b2c3d4"
    },
    {
      "date": "2026-11-15",
      "location": "B",
      "telegram_id": 123456789,
      "time_slot": "18:00-19:00",
      "booking_id": "f9e8d7c6"
    }
  ]
}
```

**Как читать ответ:**

| Поле | Что это |
|---|---|
| `booking_id` | ID брони. Его отправляем при переносе |
| `time_slot` | Один час игры `"HH:MM-HH:MM"`. Его отправляем как `old_slot` |
| `date` | Дата игры `YYYY-MM-DD` |
| `location` | Площадка (`"A"` или `"B"`). **При переносе площадка не меняется** |

**Важно: один слот = одна запись в списке.** Бронь на 2 часа приходит как 2 элемента с одинаковым `booking_id` (в примере выше `a1b2c3d4`). Для экрана «Мои брони» их нужно сгруппировать:

```js
const groups = {};
for (const b of data.bookings) {
  (groups[b.booking_id] ??= { booking_id: b.booking_id, date: b.date, location: b.location, slots: [] })
    .slots.push(b.time_slot);
}
// groups["a1b2c3d4"] = { date: "2026-11-12", location: "A", slots: ["12:00-13:00", "13:00-14:00"] }
```

В списке только будущие брони. Если пользователь не найден — **404** `{"error": "Пользователь не найден"}`.

## 3. Шаг 2. Показать свободные слоты на новую дату

Пользователь выбирает новую дату, показываем свободные часы **той же площадки** (`location` из брони).

`POST /free-slots`

```json
{ "location": "A", "year": 2026, "month": 11, "day": 14 }
```

**Ответ 200:** объект `{слот: сколько_свободно}`. `0` — занят, больше `0` — свободен.

```json
{
  "10:00-11:00": 1,
  "11:00-12:00": 0,
  "12:00-13:00": 1,
  "16:00-17:00": 2
}
```

Показываем пользователю только слоты со значением `> 0`.
>
> Свободность — только подсказка для UI. Сервер проверяет её ещё раз при переносе, за время между шагами слот могли занять (см. ответ 409).

## 4. Шаг 3. Отправить перенос

`POST /profile/reschedule_booking`

### Тело запроса

| Поле | Тип | Обяз. | Описание |
|---|---|---|---|
| `telegram_id` | число | да | Telegram ID пользователя |
| `booking_id` | строка | да | `booking_id` из шага 1 |
| `new_date` | строка `YYYY-MM-DD` | да | Новая дата. **Одна на весь запрос**: все переносимые слоты уезжают на эту дату |
| `moves` | массив | да, минимум 1 | Что переносим (см. ниже) |

Элемент `moves`:

| Поле | Описание |
|---|---|
| `old_slot` | Текущий слот брони (`time_slot` из шага 1) |
| `new_slot` | Новый слот на `new_date` (из ответа `/free-slots`) |

**Слоты брони, которых нет в `moves`, остаются как были** (на прежней дате и времени).

### Пример 1. Бронь из 2 слотов, переносим только один

Было: 12 ноября, `12:00-13:00` и `13:00-14:00`. Хотим сдвинуть только второй час на 14 ноября, на 16:00.

```json
{
  "telegram_id": 123456789,
  "booking_id": "a1b2c3d4",
  "new_date": "2026-11-14",
  "moves": [
    { "old_slot": "13:00-14:00", "new_slot": "16:00-17:00" }
  ]
}
```

Стало: 12 ноября `12:00-13:00` (не тронут) и 14 ноября `16:00-17:00`.

### Пример 2. Переносим оба слота

```json
{
  "telegram_id": 123456789,
  "booking_id": "a1b2c3d4",
  "new_date": "2026-11-14",
  "moves": [
    { "old_slot": "12:00-13:00", "new_slot": "16:00-17:00" },
    { "old_slot": "13:00-14:00", "new_slot": "17:00-18:00" }
  ]
}
```

### Пример 3. Бронь из одного слота, тот же день, другое время

Дату оставляем той же, меняется только час:

```json
{
  "telegram_id": 123456789,
  "booking_id": "f9e8d7c6",
  "new_date": "2026-11-15",
  "moves": [
    { "old_slot": "18:00-19:00", "new_slot": "20:00-21:00" }
  ]
}
```

### Пример 4. curl

```bash
curl -X POST "https://<host>/profile/reschedule_booking" \
  -H "Content-Type: application/json" \
  -d '{
        "telegram_id": 123456789,
        "booking_id": "a1b2c3d4",
        "new_date": "2026-11-14",
        "moves": [{"old_slot": "13:00-14:00", "new_slot": "16:00-17:00"}]
      }'
```

### Успешный ответ — 200

```json
{ "status": "success", "message": "Бронь успешно перенесена" }
```

После успеха перезапросите `GET /profile/{telegram_id}`, чтобы показать актуальные брони.

Перенос **атомарный**: он либо проходит целиком, либо не меняется ничего. Если вы переносите два слота и второй оказался занят, первый тоже не перенесётся.

## 5. Все ответы и что с ними делать

Во всех ошибках тело — `{"error": "<текст>"}`, кроме 422 (формат FastAPI, см. ниже). Поле `error` написано на русском и годится для показа пользователю.

| HTTP | Пример тела | Причина | Что делать во фронтенде |
|---|---|---|---|
| **200** | `{"status":"success","message":"Бронь успешно перенесена"}` | Всё хорошо | Показать успех, обновить список броней |
| **400** | `{"error":"Слоты в moves не должны повторяться"}` | Один и тот же `old_slot` или `new_slot` дважды | Баг фронтенда, не должно возникать |
| **400** | `{"error":"Неизвестные слоты: ['25:00-26:00']"}` | `new_slot` не из сетки слотов | Брать слоты только из `/free-slots` |
| **400** | `{"error":"Нельзя перенести бронь на время в прошлом"}` | Новый слот уже начался | Не показывать прошедшие слоты, предложить выбрать другое время |
| **400** | `{"error":"Перенос возможен не позднее чем за 6 часов до игры"}` | До начала одного из переносимых слотов осталось меньше 6 часов | Показать сообщение, перенос недоступен (см. правило ниже) |
| **400** | `{"error":"Среди переносимых слотов есть слот, которого нет в брони"}` | `old_slot` не принадлежит этому `booking_id` | Брать `old_slot` только из шага 1 |
| **400** | `{"error":"Слот 13:00-14:00 уже есть в этой брони"}` | Новый слот совпал со слотом этой же брони, который остаётся на месте (например, переносим 12:00 на 13:00 того же дня, а 13:00 уже у пользователя) | Попросить выбрать другое время |
| **403** | `{"error":"У вас нет доступа к этому бронированию"}` | Бронь не найдена или принадлежит другому `telegram_id` | Обновить список броней, показать ошибку |
| **409** | `{"error":"Слот 16:00-17:00 уже занят"}` | Слот заняли, пока пользователь выбирал | Перезапросить `/free-slots`, предложить выбрать снова |
| **409** | `{"error":"Цена слота 17:00-18:00 (150000.0) не совпадает с ценой текущего слота (100000.0)"}` | Новый слот стоит иначе, чем старый (например, вечер дороже) | Сообщить, что можно переносить только на слот той же стоимости |
| **422** | `{"detail":[{"loc":["body","new_date"],"msg":"...","type":"date_from_datetime_parsing"}]}` | Неверный формат тела: дата не `YYYY-MM-DD`, пустой `moves`, не хватает поля | Баг фронтенда, проверить формат |
| **500** | `{"error":"Ошибка при переносе брони: ..."}` | Внутренняя ошибка (изменения откатились, бронь не пострадала) | «Что-то пошло не так, попробуйте позже» |
| **503** | `{"error":"Ошибка сервера"}` | Ошибка при проверке брони | То же, можно повторить позже |

### Про ошибку цены (409)

Цены на разные часы могут отличаться. Перенос разрешён **только на слот той же цены** (доплат и возвратов нет). Чтобы не получать эту ошибку, цены можно проверить заранее через `POST /get-price`:

```json
{ "location": "A", "time_slot": "16:00-17:00" }
```

```json
{ "location": "A", "time_slot": "16:00-17:00", "price": 100000.0 }
```

Цену текущего слота запросите так же (`time_slot` из брони) и показывайте для переноса только слоты с равной ценой.

## 6. Правила и ограничения

1. **Не позднее чем за 6 часов до игры.** Проверяется **отдельно для каждого переносимого слота** (по Ташкенту). Пример: сейчас 08:30, у пользователя слоты 12:00, 13:00 и 15:30.
   - 12:00 начнётся через 3,5 ч → перенести **нельзя**;
   - 13:00 начнётся через 4,5 ч → **нельзя**;
   - 15:30 начнётся через 7 ч → **можно**.   
   Слоты, которые вы не переносите, на проверку не влияют. Для UI: скрывайте или блокируйте кнопку «Перенести» у слотов, до которых меньше 6 часов.
2. **Новое время должно быть в будущем** (по Ташкенту).
3. **Площадка не меняется.** Новые слоты ищутся на той же площадке (`location` брони).
4. **Дата одна на весь запрос.** Если нужно разнести слоты одной брони на разные даты, отправьте два запроса, по одному на каждую дату.
5. **`old_slot` и `new_slot` не должны повторяться** внутри одного запроса.
6. **Цена нового слота = цене старого** (иначе 409).
7. **Слоты по 1 часу**, формат строго `"HH:MM-HH:MM"`, как приходят из `/free-slots`.
8. `booking_id` при переносе не меняется, меняются только дата и время слотов.

## 7. Готовый пример кода

```js
const API = "https://<host>";

async function loadBookings(telegramId) {
  const res = await fetch(`${API}/profile/${telegramId}`);
  if (!res.ok) throw new Error((await res.json()).error);
  return res.json();
}

async function loadFreeSlots(location, isoDate) {
  const [year, month, day] = isoDate.split("-").map(Number);
  const res = await fetch(`${API}/free-slots`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ location, year, month, day }),
  });
  if (!res.ok) throw new Error("Не удалось загрузить свободные слоты");
  const slots = await res.json();
  return Object.keys(slots).filter((slot) => slots[slot] > 0); // только свободные
}

async function rescheduleBooking({ telegramId, bookingId, newDate, moves }) {
  const res = await fetch(`${API}/profile/reschedule_booking`, {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({
      telegram_id: telegramId,
      booking_id: bookingId,
      new_date: newDate,   // "2026-11-14"
      moves,               // [{ old_slot: "13:00-14:00", new_slot: "16:00-17:00" }]
    }),
  });
  const data = await res.json();

  if (res.ok) return { ok: true };

  // 409 — слот занят или другая цена: можно предложить выбрать заново
  // 422 — ошибка формата (у FastAPI поле detail вместо error)
  const message = data.error ?? "Некорректный запрос";
  return { ok: false, status: res.status, message };
}

// Использование: переносим только второй час брони a1b2c3d4
const result = await rescheduleBooking({
  telegramId: 123456789,
  bookingId: "a1b2c3d4",
  newDate: "2026-11-14",
  moves: [{ old_slot: "13:00-14:00", new_slot: "16:00-17:00" }],
});
if (!result.ok) alert(result.message);
```

## 8. Чек-лист для UI

- [ ] Брони сгруппированы по `booking_id`, у каждой видны все её слоты.
- [ ] Пользователь может выбрать **один, несколько или все** слоты брони для переноса.
- [ ] Слоты, до которых меньше 6 часов, недоступны для переноса.
- [ ] После выбора даты запрашивается `/free-slots` для **площадки этой брони**, показываются слоты с `> 0`.
- [ ] Для каждого выбранного старого слота выбран свой новый слот. Нельзя выбрать один новый слот для двух старых.
- [ ] Показываются только слоты той же цены (или обрабатывается 409 по цене).
- [ ] Обработаны 409 (слот занят: перезапросить слоты) и 400 про 6 часов.
- [ ] После успешного переноса список броней перезагружается.
