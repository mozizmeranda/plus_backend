# Перенос брони — `POST /profile/reschedule_booking`

Переносит один, несколько или все слоты брони на другую дату/время (один общий `new_date`).
**Всё время — по Ташкенту** (`Asia/Tashkent`). Время сервера (Германия) клиент учитывать не должен.

Код: [profile_endpoint.py](profile_endpoint.py), [helpers.py](helpers.py), `Database.reschedule_booking` в `database/database.py`.

---

## Откуда взять `booking_id` и слоты

`GET /profile/{telegram_id}` возвращает будущие брони пользователя. Каждый слот — отдельный элемент:

```json
{
  "name": "Иван",
  "phone": "+998901234567",
  "bookings": [
    {"date": "2026-11-12", "location": "A", "telegram_id": 123456789, "time_slot": "12:00-13:00", "booking_id": "a1b2c3d4"},
    {"date": "2026-11-12", "location": "A", "telegram_id": 123456789, "time_slot": "13:00-14:00", "booking_id": "a1b2c3d4"}
  ]
}
```

Слоты с одинаковым `booking_id` относятся к одной брони. `booking_id` и `time_slot` (как `old_slot`) подставляются в запрос переноса.

---

## Запрос

`POST {ROOT_PATH}/profile/reschedule_booking`
`Content-Type: application/json`

| Поле | Тип | Описание |
|---|---|---|
| `telegram_id` | int | Telegram ID владельца брони |
| `booking_id` | str | ID брони (`bookings.booking_id`) |
| `new_date` | str | Новая дата `YYYY-MM-DD` (Ташкент), общая для всех переносимых слотов |
| `moves` | list | Какие слоты переносим: список `{"old_slot", "new_slot"}` |

Элемент `moves`:

| Поле | Описание |
|---|---|
| `old_slot` | Текущий слот брони, `"HH:MM-HH:MM"` |
| `new_slot` | Новый слот на `new_date`, `"HH:MM-HH:MM"`, из сетки `TIME_SLOTS` (1 час) |

**Слоты брони, которых нет в `moves`, остаются на месте.**

### Примеры

Бронь на 12:00–13:00 и 13:00–14:00. Переносим **только второй** слот:

```json
{
  "telegram_id": 123456789,
  "booking_id": "a1b2c3d4",
  "new_date": "2026-11-12",
  "moves": [
    {"old_slot": "13:00-14:00", "new_slot": "16:00-17:00"}
  ]
}
```

Переносим **оба**:

```json
{
  "telegram_id": 123456789,
  "booking_id": "a1b2c3d4",
  "new_date": "2026-11-12",
  "moves": [
    {"old_slot": "12:00-13:00", "new_slot": "16:00-17:00"},
    {"old_slot": "13:00-14:00", "new_slot": "17:00-18:00"}
  ]
}
```

### Правила

- `old_slot` должен существовать в брони, `old_slot` и `new_slot` в запросе не должны повторяться.
- `new_slot` — из `TIME_SLOTS`, в будущем (по Ташкенту).
- Новый `(new_date, new_slot)` не должен совпадать со слотом этой же брони, который остаётся на месте.
- **Не позднее чем за 6 часов** до начала каждого переносимого слота. Остальные слоты брони не учитываются: если первый слот начнётся через 3 часа, а второй через 8, второй можно перенести, первый нет.
- **Цена нового слота должна совпадать с ценой старого** (сравнивается с `bookings.price`). Иначе перенос отклоняется, ничего не меняется.
- Локация не меняется. Свободные слоты можно посмотреть через `POST /free-slots`.
- Авторизация (API-ключ) для этого роутера не требуется.

## Ответы

| HTTP | Тело | Когда |
|---|---|---|
| 200 | `{"status": "success", "message": "Бронь успешно перенесена"}` | Перенос выполнен |
| 400 | `{"error": "Слоты в moves не должны повторяться"}` | Дубли в `old_slot` или `new_slot` |
| 400 | `{"error": "Неизвестные слоты: [...]"}` | `new_slot` не из `TIME_SLOTS` |
| 400 | `{"error": "Нельзя перенести бронь на время в прошлом"}` | Новый слот уже прошёл |
| 400 | `{"error": "Перенос возможен не позднее чем за 6 часов до игры"}` | До одного из переносимых слотов меньше 6 часов |
| 400 | `{"error": "Среди переносимых слотов есть слот, которого нет в брони"}` | `old_slot` не принадлежит брони |
| 400 | `{"error": "Слот ... уже есть в этой брони"}` | Новый слот совпал с остающимся слотом брони |
| 403 | `{"error": "У вас нет доступа к этому бронированию"}` | Бронь не найдена или чужая |
| 409 | `{"error": "Слот ... уже занят"}` | Новый слот заполнен до лимита корта |
| 409 | `{"error": "Цена слота ... не совпадает с ценой текущего слота ..."}` | Цена нового слота отличается от старой |
| 422 | стандартная ошибка FastAPI | Неверный формат тела (`new_date`, пустой `moves` и т.п.) |
| 500 | `{"error": "Ошибка при переносе брони: ..."}` | Непредвиденная ошибка (изменения откатываются) |
| 503 | `{"error": "Ошибка сервера"}` | Ошибка при проверке доступа |

---

## Что происходит на сервере

1. Валидация запроса (дубли, сетка `TIME_SLOTS`, время в будущем).
2. Проверка владельца брони, принадлежности `old_slot` и правила 6 часов — только для переносимых слотов.
3. В **одной транзакции**:
   - проверяется, что новый слот не дублирует остающийся слот брони;
   - проверяется цена каждого нового слота;
   - удаляются события календаря (`single_events`) и строки `bookings` только переносимых слотов;
   - для каждого нового слота проверяется вместимость и создаются новые `single_events` и строки `bookings` (тот же `booking_id` и скриншот оплаты, `calendar_id` — id нового события).
4. Если слот занят, цена не совпала или произошла ошибка — всё откатывается, бронь остаётся нетронутой.

## Примеры вызова

```bash
curl -X POST "https://<host>/profile/reschedule_booking" \
  -H "Content-Type: application/json" \
  -d '{
        "telegram_id": 123456789,
        "booking_id": "a1b2c3d4",
        "new_date": "2026-11-12",
        "moves": [{"old_slot": "13:00-14:00", "new_slot": "16:00-17:00"}]
      }'
```

```js
const res = await fetch(`${API}/profile/reschedule_booking`, {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    telegram_id: 123456789,
    booking_id: "a1b2c3d4",
    new_date: "2026-11-12",
    moves: [{ old_slot: "13:00-14:00", new_slot: "16:00-17:00" }],
  }),
});
const data = await res.json();
if (!res.ok) alert(data.error);
```
